# Отклики и переписка

Соискатель откликается на вакансию, которую работодатель разместил через сайт (`origin = 'direct'`), работодатель разбирает отклики и переписывается с кандидатом. У вакансий из внешних источников отклика нет: у них кнопки "Позвонить", "Написать" и "Оригинал".

## Код

| Файл | Что делает |
| --- | --- |
| `rabota/messaging/schema.py` | колонки и индексы поверх базовой схемы, вызывается из `rabota.db.connect`, повтор безопасен |
| `rabota/messaging/rules.py` | пределы длины, статусы, причины жалоб, очистка и проверка текста, исключения |
| `rabota/messaging/service.py` | вся логика без веба: отклик, списки, статусы, переписка, блокировка, жалобы, настройки писем |
| `rabota/messaging/notify.py` | письма и подписанные ссылки отписки |
| `rabota/messaging/erase.py` | что происходит с перепиской при удалении аккаунта |
| `rabota/web/messages_routes.py` | страницы и POST-обработчики |
| `rabota/web/templates/messages/` | шаблоны страниц, блок отклика на странице вакансии, блок кабинета |
| `rabota/web/templates/email/new_response.txt`, `new_message.txt` | тексты писем |
| `rabota/web/static/messages.css`, `messages.js` | стили и небольшой скрипт (счётчик знаков, Ctrl+Enter, защита от двойной отправки) |

## Данные

Используются таблицы `applications`, `conversations`, `messages`, `user_blocks`, `reports`. Добавлено:

- `applications.contact_name`, `contact_phone`: имя и телефон на момент отклика (телефон только если соискатель разрешил показать);
- `applications.withdrawn_at`: отзыв отклика (колонка `status` ограничена значениями `new`, `viewed`, `invited`, `rejected`, отзыв хранится отдельной отметкой);
- `applications.status_changed_at`;
- `conversations.title`: название вакансии на момент отклика, переписка остаётся понятной после удаления вакансии;
- `reports.snapshot`: JSON с копией сообщения для жалоб на сообщения;
- `users.notify_responses`, `users.notify_messages`: письма можно отключить (по умолчанию включены).

Один отклик на пару "вакансия, соискатель" (уникальный индекс), после отзыва новый отклик на ту же вакансию тоже нельзя. На отклик создаётся один тред; сопроводительное сообщение, если оно есть, становится первым сообщением треда.

## Жалобы на сообщения (для модерации)

Жалоба пишется в `reports`: `target_type = 'message'`, `target_id` номер сообщения, `reason` причина (и комментарий после двоеточия), `status = 'new'`, `reporter_user_id` автор жалобы. В `snapshot` лежит JSON: `conversation_id`, `message_id`, `sender_user_id`, `body`, `sent_at`, `comment`. Модерация читает текст из `snapshot`: сообщение может быть удалено вместе с аккаунтом. Повторная жалоба того же пользователя на то же сообщение новой записи не создаёт.

## Правила

- Отклик: роль соискатель, вакансия видна на сайте (одобрена, не истекла), работодатель не заблокировал этого соискателя (ответ нейтральный, без пояснения), второй отклик запрещён. Сопроводительное сообщение до 2000 знаков.
- Статусы работодателя: просмотрен, приглашён, отказ. Статус "новый" ставится при отклике, "просмотрен" ставится сам при открытии отклика работодателем. Отозванный отклик менять нельзя.
- Переписка: текст очищается (управляющие и невидимые знаки, лишние пробелы и пустые строки), до 2000 знаков, не больше 2 ссылок. Не больше 3 сообщений подряд, пока собеседник не ответил. Одинаковое сообщение в течение минуты не принимается. После отказа соискатель писать не может, работодатель может. После отзыва тред закрыт для обоих.
- Блокировка: действует на все треды пары. Заблокированный видит нейтральное "Пользователь не принимает сообщения".
- Чужой отклик или тред: всегда 404, не 403.
- Защита: CSRF-токен и проверка Origin на каждом POST, лимиты частоты через `rabota.accounts.ratelimit`: `apply_user`, `apply_ip`, `message_user`, `message_day`, `status_user`, `block_user`, `report_user`, `notify_mail`, `unsubscribe_ip` (значения по умолчанию в `messages_routes.LIMITS`, настройки приложения главнее).

## Страницы

`/vacancy/<id>/apply` (форма отклика, также блок на странице вакансии), `/responses`, `/responses/<id>` (+ `POST .../status`, `POST .../withdraw`), `/messages`, `/messages/<id>` (+ `POST`, `.../block`, `.../unblock`, `.../report`), `/notifications`, `/notifications/unsubscribe/<токен>`. Старые адреса `/cabinet/responses` и `/cabinet/messages` перенаправляют на новые. Все страницы закрыты от индексации и не кэшируются. Счётчики и последние отклики показаны в кабинетах (`/cabinet/seeker`, `/cabinet/employer`).

## Почта

Письмо работодателю о новом отклике и получателю о новом сообщении. В письме только название вакансии, ссылка на сайт и ссылка отписки: имён, контактов и текста сообщений нет. Письмо о сообщении уходит только за первое непрочитанное сообщение треда. Не больше 12 писем в час на одного получателя. Отписка по ссылке из письма работает без входа: GET показывает вопрос, отключает только POST с CSRF-токеном. Настройки: `/notifications` (ссылка на странице `/account`). Сбой почты не мешает отклику и отправке сообщения.

## Персональные данные

При удалении аккаунта (`accounts.service.delete_account`) удаляются отклики, треды, сообщения и блокировки пользователя; тред пропадает и у собеседника. Жалоба на сообщение остаётся на срок хранения жалоб, но в копии сообщения автор обезличивается (`sender_user_id = null`), а свободный текст жалобы удаляется, если жаловался удаляемый пользователь. Вакансия удалена по сроку: отклик исчезает, переписка остаётся с сохранённым названием.

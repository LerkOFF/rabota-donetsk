# Сайт

Серверный рендер: FastAPI, Jinja2, чистый CSS, минимум JavaScript. Код в `rabota/web/`.

## Запуск

```
.venv/bin/uvicorn rabota.web.app:app --port 8000
```

База берётся из `DB_PATH` (по умолчанию `data/rabota.db`), таблица `vacancies`. Для разработки и скриншотов есть выдуманные данные:

```
.venv/bin/python scripts/seed_demo.py              # data/demo.db
DB_PATH=data/demo.db .venv/bin/uvicorn rabota.web.app:app --port 8000
```

За прокси (nginx) для лимита частоты по адресу клиента задайте `WEB_TRUST_PROXY=1`.

## Страницы

| Адрес | Что |
| --- | --- |
| `/` | поиск, быстрые условия, сферы, свежие вакансии |
| `/vacancies` | лента с фильтрами, сортировкой и страницами |
| `/employers` | страница для работодателей: преимущества, шаги, вопросы |
| `/company/<id>` | страница работодателя (если записи в `companies` нет, показывается заготовка и ставится `noindex`) |
| `/vacancy/<id>` | карточка, контакты, "также публикуют", похожие, жалоба |
| `/profession/<название>`, `/district/<название>`, `/city/<название>` | страницы для поисковиков |
| `/razmestit` | форма размещения, вакансия сохраняется со статусом `hidden` до проверки; у вошедшего работодателя вакансия привязывается к нему и его компании, после отправки открывается `/cabinet/vacancies` |
| `/legal`, `/legal/<документ>` | юридические документы |
| `/legal/request` | форма запроса по персональным данным (закрыта от индекса) |
| `/admin/*` | админка, см. `docs/ADMIN.md` |
| `/login`, `/register`, `/account`, `/cabinet`, `/logout` (POST) | аккаунты, подключены отдельным модулем |
| `/cabinet/employer`, `/cabinet/seeker` | сводки кабинетов: у работодателя вакансии по статусам, что требует внимания, новые отклики, непрочитанные сообщения, компания; у соискателя отклики, непрочитанные сообщения и быстрые ссылки |
| `/cabinet/vacancies` | кабинет работодателя: список его вакансий с состоянием, датами и откликами, фильтр по состоянию, страницы по 20 |
| `/cabinet/vacancies/<id>/edit`, `.../delete` | правка вакансии (те же поля и проверки, что у `/razmestit`) и удаление с подтверждением |
| `POST /cabinet/vacancies/<id>/close`, `.../raise` | закрыть вакансию, поднять или опубликовать снова |
| `/cabinet/company` | карточка компании: название, сайт, описание, город, телефон и почта для новых вакансий |
| `/about`, `/sitemap.xml`, `/sitemap-<вид>-<N>.xml`, `/robots.txt` | служебные (правила поиска: `docs/SEO.md`) |

В ленту попадают только `kind="vacancy"`, `status="active"`, без `duplicate_of` и без пометки `suspicious`.

## Шапка и пользователь

Шапка берёт пользователя из `request.state.user` (словарь `id`, `email`, `name`, `role` или `None`; нет атрибута: гость). Роли: `job_seeker`, `employer`, `admin`. Гость видит "Войти" и "Регистрация", соискатель меню Кабинет, Отклики, Сообщения, Профиль, работодатель Кабинет, Мои вакансии, Отклики, Сообщения, Компания, Профиль и кнопку "Разместить вакансию". Резюме и избранного на сайте нет, обещать их нельзя ни в меню, ни в текстах. Адреса пунктов заданы константами меню в `rabota/web/app.py`. Выход: форма POST на `/logout` с полем `csrf_token`.

## Кабинет работодателя

Код: `rabota/cabinet.py` (правила без веба), `rabota/web/cabinet_routes.py` (страницы), шаблоны `templates/cabinet/`, стили `static/cabinet.css`. Только роль `employer` (соискателю и администратору 403, гостю вход), чужая вакансия всегда 404, все POST с CSRF-токеном, страницы закрыты от индекса и не кэшируются.

Состояние вакансии простым языком выводится из `moderation_status`, `status` и срока:

| Состояние | Когда | Что можно |
| --- | --- | --- |
| На проверке | `moderation_status = pending` | править, удалить |
| Отклонена | `rejected`, причина из модерации показана в списке и над формой | править (уйдёт на проверку снова), удалить |
| Опубликована | одобрена, `active`, срок идёт; показано "на сайте до" и сколько дней осталось | править, поднять, закрыть, удалить |
| Закрыта | `status = closed` | править, открыть снова, удалить |
| Срок истёк | `expired` или с последней публикации прошло 21 день | править, опубликовать снова, удалить |
| Скрыта | скрыл модератор, жалобы или пометка подозрительной | только удалить |

Правила:

- **Поднять и продлить.** Повторная публикация ставит `published_at` и `last_seen_at` в текущий момент: срок 21 день начинается заново, вакансия поднимается в ленте. Не чаще раза в сутки (с момента последней публикации или одобрения), иначе в списке вместо кнопки видно, через сколько можно. Истёкшая вакансия возвращается на сайт. Закрытая вакансия, у которой срок ещё идёт, просто открывается снова без сдвига дат и без ограничения. Вакансию на проверке, отклонённую или скрытую модератором поднять нельзя.
- **Правка.** Те же поля и проверки, что у публичной формы (`rabota/web/postform.py`). Опубликованная (или закрытая, или с истёкшим сроком) вакансия снова уходит на проверку и скрывается с сайта, только если изменились **оплата** (от, до, период, ежедневная выплата), **контакты** (телефон, Telegram, почта) или **текст** (профессия, название организации, описание, требования). Остальные правки (график, город, район, сфера, формат, занятость, возраст, опыт) применяются сразу, вакансия остаётся опубликованной. Правка вакансии, которая уже на проверке, проверку не сбивает. Отклонённая вакансия после правки всегда отправляется на проверку, причина отказа очищается. Владелец, происхождение и даты правкой не меняются.
- **Закрыть.** `status = closed`, страница вакансии отвечает 410, отклики и переписки сохраняются.
- **Удалить.** Через страницу подтверждения: вакансия, отклики на неё и жалобы удаляются, переписки с кандидатами остаются с сохранённым названием. На странице подтверждения число откликов показано, предлагается закрыть вместо удаления.
- **Размещение.** Вошедший работодатель отправляет `/razmestit` с токеном CSRF: вакансия получает `owner_user_id`, `company_id` (компания создаётся из названия организации или имени аккаунта, если её ещё нет), `origin = direct` (отклик на сайте), проверку и перенаправление на `/cabinet/vacancies?done=posted`. Пустые название, телефон и почта в форме подставляются из карточки компании. Гость и соискатель размещают как раньше: без привязки, после отправки страница "спасибо".
- **Компания** (`/cabinet/company`): одна карточка на работодателя, название 2-120 знаков, описание до 1500, сайт `http(s)` с точкой в адресе, телефон и почта проверяются, управляющие и невидимые знаки удаляются. Данные видны на `/company/<id>` (кроме телефона и почты: они только подставляются в новые вакансии).
- Подсказки после действий передаются кодом в адресе (`?done=`, `?err=`), неизвестные коды игнорируются.

## Фильтры ленты

Параметры `/vacancies`: `q`, `where` (город или район, разбирается в `city` или `district`), `city`, `district`, `category`, `work_format`, `pay_period`, `pay_from` (оплата от, рублей в месяц; за смену, день и час считается пересчёт), `no_experience`, `side_job`, `daily`, `adult`, `direct` (только от работодателей), `sort` (`pay`: по оплате, иначе по дате), `page`. Вакансии работодателей (`origin = 'direct'`) помечены "От работодателя" и ведут на `/vacancy/<id>/apply`.

## Оформление

Токены цвета, шрифта, отступов, радиусов и теней лежат в `rabota/web/static/tokens.css`, компоненты в `site.css` используют только их. Палитра: основной синий `#2563eb` (кнопки, ссылки, активные состояния), акцент коралловый `#ff9478` (отметки, выделение оплаты), фон `#f6f8fc`; тёмная тема: фон `#0f172a`, карточки `#111c33`. Тёмная тема включается системной настройкой и переключателем. Общие правила и разбор образца: `docs/DESIGN.md`. Шрифт Onest лежит в `static/fonts/`.

## Проверки

`.venv/bin/pytest` (маршруты, запросы, оформление) и `.venv/bin/pytest -m e2e` (Chromium: мобильная и десктопная ширина, темы, формы, доступность, размеры целей нажатия, окно согласия на аналитику).

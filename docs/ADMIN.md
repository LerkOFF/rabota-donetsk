# Админка: модерация, жалобы, обращения по данным

Служебная часть сайта. Без неё публиковать нельзя: все вакансии с формы `/razmestit` попадают в очередь проверки, а жалобы и запросы по персональным данным нужно разбирать в срок.

## Доступ

- Только пользователи с ролью `admin`. Гостя отправляет на страницу входа, вошедшего без роли встречает 404 (существование раздела не раскрывается), частые попытки получают 429.
- Первый администратор: `python -m rabota make-admin <почта>`. Если пользователя с такой почтой нет, он создаётся без пароля; пароль задаётся через "Забыли пароль" на странице входа. Пароль в аргументах не передаётся. Команда повторяема: существующему пользователю роль просто выставляется.
- Все адреса `/admin/*` закрыты от индекса: заголовок `X-Robots-Tag: noindex, nofollow`, мета-тег robots, `Disallow: /admin` в robots.txt, ответы с `Cache-Control: no-store`.
- Каждое изменяющее действие (POST) требует CSRF-токен и проверяется по заголовку Origin; число действий в минуту ограничено.
- Журнал действий (`/admin/audit`, таблица `audit_log`): кто, что, когда, над чем и с какого адреса. Пароли, токены и тексты писем в журнал не попадают.

## Разделы

| Адрес | Что делает |
| --- | --- |
| `/admin` | Сводка: активные вакансии, очередь проверки, жалобы, обращения, источники с проблемами, последние ошибки, последние действия |
| `/admin/pulse` | Пульс: плитки за период со сравнением с прошлым таким же и графиком по дням (см. ниже) |
| `/admin/moderation` | Очередь вакансий с сайта (на проверке, отклонённые, скрытые, все), поиск |

| `/admin/vacancies/{id}` | Карточка: вакансия так, как её видит посетитель, история, исходный пост, все поля, решение (одобрить, отклонить с причиной, скрыть, вернуть, отметить повторяющейся), правка полей |
| `/admin/complaints`, `/admin/complaints/{id}` | Жалобы на вакансии и действия по ним |

| `/admin/audit` | Журнал действий |

## Пульс

Адрес `/admin/pulse?period=<ключ>`, ключи: `today`, `yesterday`, `7d`, `30d`, `month`, `all` (по умолчанию `7d`, неизвестный ключ тоже даёт `7d`). Код: `rabota/admin/pulse.py`, шаблон `admin/pulse.html`.

**Границы.** Считает код по местному времени Донецка (UTC+3), а не `NOW()` базы: «сегодня» начинается в местную полночь, то есть в 21:00 UTC предыдущих суток. В базе время лежит в UTC в двух видах (`2026-10-29 11:30:00` и `2026-10-29T11:30:00+00:00`), сравнение идёт по первым 19 знакам.

| Период | Границы | Сравнение |
| --- | --- | --- |
| Сегодня | с местной полуночи до сейчас | вчера до этого же времени |
| Вчера | сутки | позавчера |
| 7 дней, 30 дней | последние 7 или 30 суток, считая сегодняшние | предыдущий отрезок такой же длины |
| Месяц | с 1 числа до сейчас | прошлый месяц за те же дни (не длиннее самого месяца) |
| Всё | с самой ранней записи | нет |

**Плитки.** У каждой: число, процент к прошлому периоду, спарклайн (инлайн SVG, по часам для сегодня и вчера, по дням, а при периоде дольше 62 дней по неделям) и разбивка.

| Плитка | Откуда | Оценка сравнения |
| --- | --- | --- |
| Новые вакансии | `vacancies.created_at`, без дублей; разбивка по источникам (для размещённых на сайте метка «Разместили на сайте») | больше лучше |
| Поступило на модерацию | вакансии с `origin = 'direct'` по `created_at`; под числом сколько сейчас в очереди | без оценки |
| Скрыто | журнал действий: `vacancy.hide`, `vacancy.autohide`, `vacancy.stoplist_hide`; разбивка вручную, по жалобам, по стоп-листу | меньше лучше |
| Просрочено | вакансии, у которых `last_seen_at` + `VACANCY_TTL_DAYS` попадает в период (одобренные, не дубли, ещё не закрытые); вакансия, которую позже обновили, в более ранних периодах не считается | без оценки |
| Регистрации | `users.created_at`; разбивка по ролям | больше лучше |
| Отклики | `applications.created_at` | больше лучше |
| Жалобы | `complaints` и `reports` по `created_at` | меньше лучше |

Цвет сравнения: зелёный - изменение в хорошую сторону, красный - в плохую, серый - без оценки или без изменений. Если сравнить не с чем (нет прошлого периода или в прошлом периоде было 0), пишется «нет сравнения» или абсолютная разница.

**Нет данных.** Если таких записей в базе не было никогда или источник недоступен, плитка пишет «нет данных», а не 0. Настоящий ноль (данные есть, за период ничего не случилось) показывается как 0.

Плитки лежат в контейнере с `data-sortable="pulse-tiles"`, у каждой `data-key` и `draggable="true"`: порядок меняется перетаскиванием.

## Система

`GET /admin/system`, код в `rabota/admin/system.py`. Каждый блок собирается отдельно: если чего-то нет (воркера, папки копий, git, файла журнала), блок показывает «нет данных», а страница открывается.

| Блок | Откуда берётся |
| --- | --- |
| Воркер | файл сердцебиения (`HEARTBEAT_PATH`, по умолчанию `data/worker.heartbeat`): работает до 3 минут, дальше молчит, файла нет: не запущен |
| Опросники источников | список ожидаемых источников из `rabota.realtime.health.expected_sources` и таблица `ingest_state` (последний успех, последняя попытка, ошибка) |
| Фоновые задачи | ежедневная уборка старых вакансий (отметка `job:expire` в `ingest_state`, пишет воркер) и ночная копия базы (возраст свежего файла `rabota-*.db*` в `BACKUP_DIR`) |
| Очереди | вакансии на проверке, открытые жалобы, жалобы на сообщения, запросы по данным (в работе и просроченные), источники с ошибкой, письма в папке отправки при `MAIL_BACKEND=file` |
| Интеграции | только «настроено» или «не настроено» и нейтральное описание: ВК, hh.ru, слушатель Telegram, прокси Telegram, Яндекс Метрика, IndexNow, почта, модель или распознавание афиш, оповещения, токен `/healthz/deep`. Значения ключей, адресов и логинов не читаются в страницу |
| Диск и база | занятость диска, где лежит база, размер файла базы и журнала записи, число вакансий, постов и пользователей |
| Версия | короткий хеш коммита и его дата (`git log -1`, при отсутствии git читается `.git/HEAD`), версия Python, режим |
| Журнал | выбор источника: файл из `LOG_FILE` (если задан), на проде ещё `journalctl` служб `rabota-web` и `rabota-worker`, журнал развёртываний `/var/log/rabota/deploy.log`. Последние 120 строк, новые сверху, фильтр по тексту `?log=...&grep=...`. Строки с токенами, паролями, ключами, куками и адресами с логином и паролем не показываются вовсе (сколько скрыто, написано под журналом). Выбирается только ключ источника, произвольные пути не читаются |

Состояния источника: работает (последний успех не старше половины порога), опаздывает (старше половины порога), молчит (старше порога: четыре интервала опроса, не меньше десяти минут), ошибка (последняя попытка закончилась сбоем позже последнего успеха), нет данных (успеха ещё не было).

Блоки страницы переставляются перетаскиванием (разметка `data-sortable`, порядок запоминает браузер).

## Настройки

`GET/POST /admin/settings`, код в `rabota/admin/settings.py`. Схема лежит в коде (`SCHEMA`): ключ, группа, подпись, тип (`int`, `bool`, `text`), умолчание, границы, подсказка. Умолчание для значений из `.env` читается на лету, поэтому пока владелец ничего не менял, действует `.env`.

- Таблица `settings` хранит только изменённое. Если сохранено значение, равное умолчанию, строка удаляется и настройка снова «как в `.env`».
- Журнал `settings_log`: кто, когда, что, было, стало, адрес. Он показан внизу страницы, и каждое сохранение пишется ещё и в общий журнал действий (`settings.save`).
- Только POST с CSRF и Origin. Значения проверяются по схеме; при любой ошибке не сохраняется ничего, страница возвращается с кодом 422, ошибки видны у полей, введённое сохраняется. Изменённые поля подсвечены, рядом показано умолчание.
- Читать настройку в коде нужно через `settings.effective(conn, ключ)`: сначала таблица, иначе `.env` и умолчание; сбой чтения возвращает умолчание.

Что подключено сейчас:

| Настройка | Где действует |
| --- | --- |
| Срок жизни вакансии (`vacancy_ttl_days`) | ежедневная уборка воркера и команда `expire`: вакансии скрываются по этому сроку. Показ на сайте и в кабинете ограничен `VACANCY_TTL_DAYS` из `.env`: больше него без перезапуска вакансию не показать (страница предупреждает) |
| Хранение скрытых (`expired_keep_days`) | удаление давно скрытых вакансий и копий фото |
| Порог автоскрытия по жалобам (`complaint_autohide_threshold`) | сразу на сайте: форма жалобы, разделы жалоб в админке |
| Регистрация открыта (`registration_open`) | сразу: страницы `/register` |
| Пояснение при закрытой регистрации (`registration_closed_note`) | строка на странице «Регистрация откроется позже» |

Города показа (`SERVICE_CITIES`) пока задаются только в `.env`: условие выдачи собирается при запуске сайта.

## Вакансии

Раздел `/admin/vacancies` показывает все записи таблицы `vacancies`, а не только выдачу: скрытые, просроченные, дубли, подозрительные, города вне `SERVICE_CITIES`, вакансии на проверке и не-вакансии (набор на службу, услуги). Код: `rabota/admin/vacancies.py` (выборки, история, повтор), маршруты `rabota/web/admin_vacancies.py`.

Над списком плитки: всего, в выдаче, на проверке, скрыты, истекли, дубли, вне выдачи по городу. Каждая плитка ведёт в список с нужным фильтром.

### Фильтры (все в адресе)

| Параметр | Значения |
| --- | --- |
| `q` | поиск: номер (до 7 цифр), телефон в любом написании (от 6 цифр, сравниваются последние 10), профессия, заголовок, работодатель, название компании. `ё` и `е`, регистр не важны |
| `prof`, `text` | часть профессии; слово в описании, требованиях или заголовке |
| `status` | `active`, `hidden`, `expired`, `closed` |
| `mod` | `pending`, `approved`, `rejected` |
| `origin` | `parsed` (собрана из источника), `direct` (от работодателя на сайте) |
| `source` | тип источника: `telegram`, `vk`, `hh` и так далее |
| `city` | город из базы или `~foreign` (не город сайта) |
| `flag` | `visible` (то же условие, что у сайта, `VISIBLE_SQL`), `invisible`, `duplicate`, `suspicious`, `stale` (активна, но срок жизни вышел), `foreign` |
| `kind` | `vacancy` или `other` |
| `period` | по дате добавления: `today`, `yesterday`, `7d`, `30d`, `month`, `all`. Сутки считаются по времени Донецка (UTC+3), границы считает код |
| `sort`, `dir` | `created` (по умолчанию), `published`, `id`, `pay`, `profession`; `asc` или `desc`. Вакансии без оплаты при сортировке по оплате идут в конце |
| `page` | страница, 25 вакансий |

Неизвестные значения отбрасываются, в запрос они не попадают (SQL параметризован, сортировка из белого списка). В строке для каждой вакансии метки состояния объясняют, почему она не в выдаче (на проверке, отклонена, скрыта, истекла, дубль №, подозрительная, срок жизни вышел, город вне выдачи).

### Карточка

Блоки: как увидит посетитель, жалобы, история, все поля записи, исходный пост источника, связанное (главная вакансия и повторы, компания, число откликов), правка полей; справа решение, видимость и отметка повтора.

- История собирается по времени из полей вакансии (добавлена, опубликована в источнике, подтверждена, срок истёк), таблицы жалоб (создана и закрыта) и журнала действий (`audit_log`, `target_type = vacancy`: одобрение, отказ, скрытие, возврат, правка, повтор). Сначала новые.
- Исходный пост берётся из `raw_posts` по паре `source` и `external_id`. У вакансий с сайта его нет.
- Телефон, ник, почта в списке и карточке показаны закрыто (`+7 949 ***-**-67`) и раскрываются кнопкой «Показать». То же с телефонами, почтой и никами внутри текста исходного поста. Без скриптов остаётся закрытый вид.
- Скрыть и вернуть: те же действия, что в модерации (`/admin/vacancies/{id}/hide`, `/restore`).
- Отметить повторяющейся: `POST /admin/vacancies/{id}/duplicate` с номером главной вакансии. Вакансия уходит из выдачи, ссылка `duplicate_of` ставится на самую главную в цепочке (цепочек не бывает: уже привязанные повторы переносятся к новой главной), себя и несуществующую указать нельзя, петля запрещена. Снять отметку: `POST /admin/vacancies/{id}/unduplicate`.
- Все действия только POST, с CSRF и проверкой Origin, пишутся в журнал (`vacancy.hide`, `vacancy.restore`, `vacancy.duplicate`, `vacancy.unduplicate`, с адресом для отметки повтора), результат показывается сообщением на один показ.

## Статусы вакансий

Вакансия видна посетителям, только если `status = active`, `moderation_status = approved`, она не дубль, не помечена подозрительной и не просрочена (см. `VISIBLE_SQL` в `rabota/web/queries.py`).

- Размещённая через сайт вакансия получает `moderation_status = pending` и `status = hidden`. Одобрение делает её `approved` и `active`, отсчёт срока жизни идёт от этого момента.
- Автор видит состояние своей вакансии и причину отказа в кабинете (`/cabinet/vacancies`), а при правке опубликованной вакансии (оплата, контакты, текст) она сама возвращается в очередь проверки (правила: `docs/WEB.md`).
- Отклонение (`rejected`) требует причину. Есть шаблоны причин (платное размещение, нет контактов, непонятное описание, не вакансия, военная служба, дубль); текст можно править. Автору уходит письмо с причиной.
- "Скрыть" оставляет `approved`, но переводит `status` в `hidden`; "Вернуть" снимает скрытие.
- Правка полей проходит ту же проверку, что и форма размещения.

## Жалобы

Причины, которые выбирает посетитель: закрыта, мошенничество, реклама, неверные данные, дубль, мои данные без моего согласия, другое. Можно оставить почту для ответа.

- Автоскрытие: когда на вакансию пожаловались `COMPLAINT_AUTOHIDE_THRESHOLD` разных людей (по умолчанию 3, `0` отключает), она скрывается и попадает в очередь с пометкой. Разных людей считаем по отпечатку адреса: HMAC от IP, сам адрес не хранится. Решение остаётся за администратором.
- Действия: скрыть вакансию, добавить в стоп-лист (по телефону, нику, названию работодателя, ключевым словам; предложения берутся из вакансии), отклонить жалобу. Если заявитель оставил почту, формируется ответ.
- Жалобы на сообщения: отклонить, отметить рассмотренной или заблокировать автора (администратора заблокировать нельзя).

## Стоп-лист

Записи: телефон, ник, название работодателя, ключевое слово. Сравнение нормализует регистр, `ё/е`, пробелы и формат телефона. Совпавшие вакансии не публикуются ни сборщиками, ни обработчиком в реальном времени (счётчик `stoplisted` в статистике запуска); при добавлении записи уже опубликованные совпадения скрываются. У записи ведётся число срабатываний и время последнего.

## Обращения по персональным данным

Публичная форма `/legal/request`: тип обращения, описание, контакт для ответа, арифметическая проверка и скрытое поле-ловушка, не более 4 обращений в час с одного адреса. Страница закрыта от индекса (`noindex, follow`): форма бесполезна в поисковой выдаче и привлекает мусорный трафик, а ссылки на правовые документы должны оставаться доступными для обхода.

В журнале у обращения: номер, дата, от кого, тип, суть, срок ответа, дата ответа, решение, исполнено ли. Сроки по типам (см. `docs/legal/requests.md`): доступ, исправление, блокировка, удаление и прочее по сроку закона; отзыв согласия 30 календарных дней; сообщение владельцу вакансии 3 рабочих дня. Рабочие дни считаются без учёта праздников. Просроченные обращения подсвечены, статус "Ждём уточнение" останавливает отсчёт. Закрыть обращение можно, только записав решение. Обращения с почты и бумажные вносятся вручную с датой получения.

Действие "Удалить данные по телефону или нику": скрывает все вакансии с этим контактом, стирает контакт из вакансий и исходных сообщений, добавляет в стоп-лист хеш контакта (сам контакт не хранится), чтобы сборщики не вернули запись, и отмечает обращение исполненным.

Выгрузка CSV экранирует ячейки, начинающиеся с `=`, `+`, `-`, `@`.

# Админка: модерация, жалобы, обращения по данным

Служебная часть сайта. Без неё публиковать нельзя: все вакансии с формы `/razmestit` попадают в очередь проверки, а жалобы и запросы по персональным данным нужно разбирать в срок.

## Доступ

- Только пользователи с ролью `admin`. Гостя отправляет на страницу входа, вошедшего без роли встречает 404 (существование раздела не раскрывается), частые попытки получают 429.
- Первый администратор: `python -m rabota make-admin <почта>`. Если пользователя с такой почтой нет, он создаётся без пароля; пароль задаётся через "Забыли пароль" на странице входа. Пароль в аргументах не передаётся. Команда повторяема: существующему пользователю роль просто выставляется.
- Все адреса `/admin/*` закрыты от индекса: заголовок `X-Robots-Tag: noindex, nofollow`, мета-тег robots, `Disallow: /admin` в robots.txt, ответы с `Cache-Control: no-store`.
- Каждое изменяющее действие (POST) требует CSRF-токен и проверяется по заголовку Origin; число действий в минуту ограничено.
- Журнал действий (`/admin/audit`, таблица `audit_log`): кто, что, когда, над чем и с какого адреса. Пароли, токены и тексты писем в журнал не попадают.

## Разделы

| Адрес | Что делает |
| --- | --- |
| `/admin` | Сводка: активные вакансии, очередь проверки, жалобы, обращения, источники с проблемами, последние ошибки, последние действия |
| `/admin/moderation` | Очередь вакансий с сайта (на проверке, отклонённые, скрытые, все), поиск |
| `/admin/vacancies/{id}` | Карточка: вакансия так, как её видит посетитель, решение (одобрить, отклонить с причиной, скрыть, вернуть), правка полей |
| `/admin/complaints`, `/admin/complaints/{id}` | Жалобы на вакансии и действия по ним |
| `/admin/reports` | Жалобы на сообщения в переписке |
| `/admin/stoplist` | Стоп-лист: телефон, ник, название работодателя, ключевое слово |
| `/admin/requests`, `/admin/requests/{id}` | Журнал обращений по персональным данным, выгрузка `/admin/requests.csv` |
| `/admin/audit` | Журнал действий |

## Статусы вакансий

Вакансия видна посетителям, только если `status = active`, `moderation_status = approved`, она не дубль, не помечена подозрительной и не просрочена (см. `VISIBLE_SQL` в `rabota/web/queries.py`).

- Размещённая через сайт вакансия получает `moderation_status = pending` и `status = hidden`. Одобрение делает её `approved` и `active`, отсчёт срока жизни идёт от этого момента.
- Отклонение (`rejected`) требует причину. Есть шаблоны причин (платное размещение, нет контактов, непонятное описание, не вакансия, военная служба, дубль); текст можно править. Автору уходит письмо с причиной.
- "Скрыть" оставляет `approved`, но переводит `status` в `hidden`; "Вернуть" снимает скрытие.
- Правка полей проходит ту же проверку, что и форма размещения.

## Жалобы

Причины, которые выбирает посетитель: закрыта, мошенничество, реклама, неверные данные, дубль, мои данные без моего согласия, другое. Можно оставить почту для ответа.

- Автоскрытие: когда на вакансию пожаловались `COMPLAINT_AUTOHIDE_THRESHOLD` разных людей (по умолчанию 3, `0` отключает), она скрывается и попадает в очередь с пометкой. Разных людей считаем по отпечатку адреса: HMAC от IP, сам адрес не хранится. Решение остаётся за администратором.
- Действия: скрыть вакансию, добавить в стоп-лист (по телефону, нику, названию работодателя, ключевым словам; предложения берутся из вакансии), отклонить жалобу. Если заявитель оставил почту, формируется ответ.
- Жалобы на сообщения: отклонить, отметить рассмотренной или заблокировать автора (администратора заблокировать нельзя).

## Стоп-лист

Записи: телефон, ник, название работодателя, ключевое слово. Сравнение нормализует регистр, `ё/е`, пробелы и формат телефона. Совпавшие вакансии не публикуются ни сборщиками, ни обработчиком в реальном времени (счётчик `stoplisted` в статистике запуска); при добавлении записи уже опубликованные совпадения скрываются. У записи ведётся число срабатываний и время последнего.

## Обращения по персональным данным

Публичная форма `/legal/request`: тип обращения, описание, контакт для ответа, арифметическая проверка и скрытое поле-ловушка, не более 4 обращений в час с одного адреса. Страница закрыта от индекса (`noindex, follow`): форма бесполезна в поисковой выдаче и привлекает мусорный трафик, а ссылки на правовые документы должны оставаться доступными для обхода.

В журнале у обращения: номер, дата, от кого, тип, суть, срок ответа, дата ответа, решение, исполнено ли. Сроки по типам (см. `docs/legal/requests.md`): доступ, исправление, блокировка, удаление и прочее по сроку закона; отзыв согласия 30 календарных дней; сообщение владельцу вакансии 3 рабочих дня. Рабочие дни считаются без учёта праздников. Просроченные обращения подсвечены, статус "Ждём уточнение" останавливает отсчёт. Закрыть обращение можно, только записав решение. Обращения с почты и бумажные вносятся вручную с датой получения.

Действие "Удалить данные по телефону или нику": скрывает все вакансии с этим контактом, стирает контакт из вакансий и исходных сообщений, добавляет в стоп-лист хеш контакта (сам контакт не хранится), чтобы сборщики не вернули запись, и отмечает обращение исполненным.

Выгрузка CSV экранирует ячейки, начинающиеся с `=`, `+`, `-`, `@`.

# Данные в реальном времени

Сайт получает вакансии сразу после публикации, а не пачкой по ручному запуску. За это отвечает воркер `python -m rabota worker`: один процесс, который держит слушатель Telegram, опрашивает VK и открытые базы по расписанию и раз в сутки скрывает устаревшие вакансии. Код лежит в `rabota/realtime/`.

## Схема

```
Telegram (Telethon, пользовательская сессия, только чтение)
   |  событие NewMessage + догон iter_messages каждые 5 минут
   v
RawPost ----------------------------------------------+
VK wall.get, каждые ~4 минуты --------------------> ingest_post --> raw_posts, vacancies
Работа России, hh.ru, Мой ЦЗН, MAX, Авито ---------+     |
(fetch() сборщиков, по интервалам)                       +--> склейка дублей, last_seen_at
                                                         +--> ingest_state (last_id, успех, ошибка)

планировщик: интервал, случайный сдвиг, нарастающая пауза при ошибках
heartbeat: data/worker.heartbeat раз в минуту
health:    python -m rabota health (код 1 при просрочке)
```

Модули:

| Файл | Роль |
| --- | --- |
| `ingest.py` | `ingest_post(conn, raw)`: сохранить сырой пост, разобрать только его (текст и картинки), сохранить вакансии, склеить дубли. Идемпотентно по `source + external_id`. `Ingestor` даёт безопасный вызов из потоков и корутин |
| `state.py` | таблица `ingest_state`: на источник `last_id`, `last_ok_at`, `last_error` |
| `telegram_listener.py` | слушатель Telegram, команда входа `tg-login` |
| `vk_poller.py` | опрос стен пабликов VK |
| `pollers.py` | открытые базы по интервалам |
| `scheduler.py` | расписание: независимые задачи, сдвиг, откат при ошибках |
| `worker.py` | команда `worker`: собирает всё вместе, SIGTERM завершает работу |
| `health.py` | команда `health` и файл сердцебиения |

## Источники и интервалы

| Источник | Способ | Интервал | Порог просрочки в `health` |
| --- | --- | --- | --- |
| Telegram, каналы из `collectors/telegram.py` и `channels.txt` | события + догон | сразу, догон 5 минут | 20 минут |
| VK, паблики из `collectors/vk.py` | `wall.get` | 4 минуты (с разбросом) | 16 минут |
| Работа России (trudvsem) | открытый API | 15 минут | 60 минут |
| hh.ru | `collectors/hh.py` | 30 минут | 120 минут |
| Мой ЦЗН | `collectors/mczn.py` | 30 минут | 120 минут |
| MAX (зеркало maxoteka.ru) | `collectors/max.py` | 20 минут | 80 минут |
| Авито | `collectors/avito.py` | 60 минут | 240 минут |
| Скрытие и удаление старого (`expire`) | `lifecycle.expire` и `purge`, плюс чистка копий фото | раз в сутки | не проверяется |

Порог просрочки: четыре интервала, но не меньше десяти минут. К каждому интервалу планировщик добавляет случайный сдвиг около 15 процентов, чтобы источники не опрашивались одновременно. После ошибки пауза растёт: минута, две, четыре и так далее, но не выше четырёх интервалов и не выше часа. Первая же удача возвращает обычный интервал. Сбой одного источника остальных не задевает.

## Настройки

Всё задаётся в `.env` на сервере (образец в `.env.example`), в репозитории секретов нет.

| Переменная | Что это | По умолчанию |
| --- | --- | --- |
| `TG_API_ID`, `TG_API_HASH` | ключи приложения Telegram, выдаются на my.telegram.org | нет: слушатель пропускается |
| `TG_SESSION_PATH` | файл сессии (Telethon добавит `.session`), хранить вне git | `data/telegram` |
| `TG_PROXY` | `socks5://host:port` или `socks5://user:pass@host:port`; `http://` и `socks4://` тоже поддерживаются; пусто - напрямую | пусто |
| `TG_CHANNELS_FILE` | файл с дополнительными каналами, по строке на канал, `@` не обязателен, `#` - комментарий | `data/channels.txt` |
| `TG_SWEEP_SECONDS` | как часто догонять пропущенное | 300 |
| `VK_ACCESS_TOKEN` | ключ VK для `wall.get`; без него опрос VK пропускается | нет |
| `MEDIA_DIR` | папка уменьшенных копий фото из Telegram | `data/media` |
| `HEARTBEAT_PATH` | файл сердцебиения | рядом с базой, `data/worker.heartbeat` |
| `WORKER_EXPIRE` | `0`: воркер не запускает ежедневный `expire` (нужен таймер) | `1` |
| `VACANCY_TTL_DAYS`, `EXPIRED_KEEP_DAYS` | срок жизни вакансии и хранение скрытых | 21 и 30 |

Список каналов Telegram: все каналы из `rabota/collectors/telegram.py` плюс строки из файла каналов. Образец файла: `deploy/channels.example.txt`.

## Первый вход в Telegram

Слушатель работает от отдельного пользовательского аккаунта. Вход делается один раз, вручную, в интерактивном терминале на том компьютере, откуда есть выход в Telegram (с прокси, если он нужен):

1. Получить `api_id` и `api_hash` на my.telegram.org и записать в `.env`: `TG_API_ID`, `TG_API_HASH`. При необходимости задать `TG_PROXY`.
2. Выполнить `python -m rabota tg-login`. Команда спросит номер телефона, код из Telegram и пароль двухфакторной защиты, если он включён. Проект номер и пароль не записывает и в журнал не пишет, остаётся файл сессии.
3. Файл сессии `data/telegram.session` получает права 600. Это ключ доступа к аккаунту: не копировать в репозиторий и не отправлять по почте. Его можно перенести на сервер вместе с `.env`.
4. Подписать аккаунт на каналы из списка. Подписанный аккаунт получает сообщения событиями сразу. Для неподписанных каналов работает догон раз в `TG_SWEEP_SECONDS`, то есть задержка до пяти минут. Подписку слушатель сам не делает, он ничего не отправляет и не меняет.

В активных сеансах Telegram слушатель виден как устройство "Rabota Donetsk reader".

## Что делает слушатель

- Только чтение. Клиент обёрнут в `ReadOnlyClient`: отправка сообщений, пересылка, правка, удаление, отметка "прочитано" и сырые запросы запрещены и падают с `ReadOnlyViolation`. Разрешены лишь получение каналов и сообщений, скачивание фото и подписка на события.
- Состояние. На канал хранится последний принятый id (`ingest_state`, ключ `telegram:<канал>`). Он только растёт.
- Догон. При старте и каждые 5 минут по каждому каналу берутся сообщения новее `last_id`: не старше срока жизни вакансии (21 день) и не больше 200 штук. Если пропущено больше 200, берутся 200 самых свежих, а не самых старых. Первый запуск берёт до 30 последних постов за 21 день. Между каналами пауза, чтобы не упереться в лимиты.
- Альбомы. Фото с одним `grouped_id` собираются в один пост: номер поста по первому сообщению, текст берётся из подписи, до 4 фото.
- Фото. Уменьшенная копия (длинная сторона 1280, JPEG) сохраняется в `data/media/<хеш>.jpg` и попадает в `image_urls` ссылкой `file://`. Фото скачивается только когда оно нужно разбору: текст короткий или в нём нет оплаты, телефона или адреса (то же правило, что и для распознавания картинок). Скачивание `file://` разрешено только из папки медиа. Старые копии удаляются вместе с ежедневным `expire`.
- Повтор события и догона. Если пост уже принят, второй раз он не разбирается и фото не скачивается.
- FloodWait. Слушатель спит указанное Telegram время плюс 5 секунд и повторяет запрос; если лимит не отпускает после трёх попыток, сессия делает паузу и начинается заново.
- Переподключение. Любой обрыв связи: новая сессия через паузу, которая растёт с 5 секунд до 5 минут. Сессия, отработавшая дольше двух минут, сбрасывает счётчик.
- Сессия отозвана или аккаунт заблокирован: слушатель останавливается (повторы бесполезны), причина пишется в `ingest_state` и видна в `health`; остальной воркер работает.
- Остановка по SIGTERM корректная: ожидание прерывается, соединение закрывается, незавершённые альбомы подберёт следующий догон.

В журнал не попадают ключи, прокси с паролем, телефон и тексты сообщений.

## Запуск

Локально:

```bash
.venv/bin/python -m rabota worker      # Ctrl+C или SIGTERM останавливают
.venv/bin/python -m rabota health      # сводка, код 1 если что-то просрочено
```

Без `TG_*` или без файла сессии слушатель Telegram пропускается с предупреждением в журнале, остальное работает. Без `VK_ACCESS_TOKEN` пропускается VK.

### На сервере (systemd)

Образцы в `deploy/`: `rabota-worker.service`, `rabota-expire.service` и `rabota-expire.timer`, `rabota-tg-proxy.service`. В них вместо реальных значений стоят заглушки `<USER>`, `<PROJECT_DIR>`, `<SSH_KEY>`, `<PROXY_USER>`, `<PROXY_HOST>`. Подставить и установить:

```bash
sed -e 's#<USER>#rabota#g' -e 's#<PROJECT_DIR>#/srv/rabota-donetsk#g' deploy/rabota-worker.service \
  | sudo tee /etc/systemd/system/rabota-worker.service
sudo systemctl daemon-reload
sudo systemctl enable --now rabota-worker
journalctl -u rabota-worker -f
```

Ежедневное `expire` по умолчанию делает сам воркер. Если нужен отдельный таймер (например, воркер запущен с `WORKER_EXPIRE=0`), поставить `rabota-expire.service` и `rabota-expire.timer`, затем `systemctl enable --now rabota-expire.timer`.

Прокси для Telegram, когда это обычный SSH-сервер: поставить `rabota-tg-proxy.service` (ключ без пароля, ключ сервера уже в `known_hosts`), включить, в `.env` указать `TG_PROXY=socks5://127.0.0.1:1080`. В юните воркера раскомментировать строки `After=` и `Wants=` для туннеля.

Сайт и воркер используют одну базу SQLite. Воркер включает режим WAL и ожидание блокировки, поэтому чтение сайта не ждёт записи.

## Мониторинг

`python -m rabota health` печатает по каждому источнику время последнего успешного опроса, порог и последнюю ошибку, а также состояние воркера по файлу `data/worker.heartbeat` (его пишет воркер раз в минуту; старше трёх минут означает, что воркер молчит). Код возврата 0 при полном порядке и 1 при любой просрочке, так что команду можно повесить на cron или на проверку мониторинга. Ключ `--json` даёт то же в машинном виде.

Какие источники проверяются, зависит от окружения: VK только при заданном `VK_ACCESS_TOKEN`, Telegram только при настроенной сессии.

Пустой ответ открытой базы не считается успехом: сборщики при блокировке или сбое возвращают пустой список, поэтому такой источник со временем станет просроченным и `health` об этом скажет. Исключение Авито (см. ниже).

## Что делать при проблемах

| Симптом в `health` или журнале | Что делать |
| --- | --- |
| "ВОРКЕР НЕ ЗАПУЩЕН" или "МОЛЧИТ" | `systemctl status rabota-worker`, `journalctl -u rabota-worker`; воркер перезапускается сам (`Restart=always`) |
| Все каналы Telegram просрочены, в ошибке "переподключение" | недоступен прокси или Telegram: проверить `TG_PROXY` и туннель (`systemctl status rabota-tg-proxy`), заменить прокси |
| "сессия Telegram не действует" | сессия отозвана или аккаунт ограничен: выполнить `python -m rabota tg-login` заново, перезапустить воркер |
| Повторяющиеся FloodWait в журнале | слишком много каналов или перезапусков; уменьшить список, увеличить `TG_SWEEP_SECONDS` |
| Канал "недоступен" | канал закрыт, переименован или удалён: поправить `channels.txt` |
| VK: ошибка 5 или 15 | ключ отозван или у паблика закрыта стена: заменить `VK_ACCESS_TOKEN` или паблик |
| hh.ru, Мой ЦЗН, MAX просрочены, ошибок нет | источник отдаёт пустой ответ (блокировка или смена разметки): проверить вручную, поправить сборщик |

Блокировки не обходятся: ни капча, ни ограничение частоты. При отказе источника воркер отступает, пауза растёт.

## Ограничения

- MAX: читается зеркало maxoteka.ru, не сам MAX. Зеркало отдаёт не больше 5 последних постов канала и индексирует их с задержкой, поэтому задержка этого источника измеряется десятками минут. Прямого чтения каналов MAX без аккаунта нет.
- Авито закрыт капчей и ограничением частоты. Сборщик при блокировке возвращает пустой список, для Авито это нормальный результат: опрос считается успешным, а `health` не краснеет. Живых данных пока нет. Обходов блокировки нет и не будет.
- Telegram: один пользовательский аккаунт, действуют лимиты Telegram. Закрытые чаты, в которые аккаунт не вступил, недоступны.
- Склейка дублей после каждого принятого поста идёт по всей таблице вакансий. На нескольких тысячах активных вакансий это доли секунды, на десятках тысяч понадобится инкрементальная склейка.
- Редактирование уже принятого поста в Telegram не отслеживается.
- Распознавание картинок идёт тем же способом, что в `python -m rabota process` (ключ модели из `.env`, без ключа - готовая разметка). Без ключа новые афиши остаются без распознавания.

## Проверки

Тесты в `tests/realtime/`, без сети и без настоящего Telegram: подмена клиента Telethon (события, сообщения, альбомы, FloodWait, обрывы), `ingest_post` (идемпотентность, дубли, повторная публикация, картинки), защита "только чтение", расписание на управляемых часах, VK и открытые базы через respx и сохранённые ответы, `health` и воркер.

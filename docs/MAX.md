# MAX: как читать каналы с вакансиями

Исследование на 29.10.2026. Цель: получать посты публичных каналов MAX (max.ru/vakansii_donetsk_dnr, vakansii_enakievo_dnr, vakansii_gorlovka, channel_rabotadnr) автоматически и как можно свежее. Код в этом документе не менялся, выводы основаны на документации и открытых страницах. Вход в аккаунты и запуск чужого кода не выполнялись.

## Как читаем сейчас

Сборщик `rabota/collectors/max.py` берёт посты из зеркала каталога maxoteka.ru: до 5 последних постов на канал, пауза 0.5-1 с между запросами, полный текст и время из JSON-LD страницы поста. Пагинация зеркала (`/channel/posts-more.php`) закрыта в robots.txt, поэтому не используется.

Что видно по зеркалу на 29.10.2026 (09:11 UTC):

- vakansii_donetsk_dnr: последний пост 28.10 18:57 UTC, лента живая.
- vakansii_enakievo_dnr: последний пост в зеркале 09.07.2026.
- vakansii_gorlovka: последний пост в зеркале 17.05.2026.
- channel_rabotadnr: постов в зеркале нет.

Неясно, что из этого "канал замолчал", а что "зеркало не обновляет канал". Проверить можно только глядя на сами каналы глазами в приложении или на web.max.ru. Это стоит сделать владельцу один раз вручную.

## Сравнение вариантов

### 1. Официальный API ботов MAX (platform-api.max.ru, dev.max.ru)

- Что даёт: бот получает события и читает сообщения и посты (`GET /messages?chat_id=...`, до 100 за запрос, фильтр по времени) только там, где он администратор. Комментарии к постам тоже только для администратора. Список каналов бота API не отдаёт, `chat_id` приходит только в событиях.
- Бот не может читать чужие каналы, где он не администратор. Добавить бота в канал может только владелец или админ канала.
- Подключение: нужен верифицированный профиль организации, ИП или самозанятого, резидента РФ, затем создание бота и модерация. Production-доставка событий только через Webhook по HTTPS (Long Polling только для отладки).
- Риски: токен можно отозвать за нарушение правил платформы. Правила требуют самостоятельно отвечать за обработку персональных данных.
- Трудозатраты: небольшие технически, но нужны регистрация профиля и согласие каждого админа канала.
- Стоимость: бесплатно.
- Вывод: подходит только для каналов, админы которых согласны добавить нашего бота. Для чужих каналов бесполезен.

### 2. Неофициальные клиенты пользовательского API (нужен личный аккаунт)

Открытые проекты на GitHub, данные на 29.10.2026:

- MaxApiTeam/PyMax (пакет `maxapi-python`): 285 звёзд, MIT, последний релиз v2.5.0 от 25.10.2026, до этого v2.4.1 (01.09) и v2.4.0 (04.08), репозиторий создан 20.08.2025. Асинхронная библиотека для внутреннего API MAX по TCP или WebSocket. Авторизация: телефон и SMS-код (`Client`) либо QR для веб-клиента (`WebClient`), сессия (token, device_id) хранится в SQLite-файле. Умеет слушать события, читать историю (`fetch_history(chat_id)`), вступать в канал по invite-ссылке (`join_channel`). В README прямое предупреждение: API неофициальный, использование может нарушать условия сервиса, блокировки аккаунтов на риске пользователя. Это единственный живой проект с заметной аудиторией.
- mochensky/max-user-api: 2 звезды, MIT, создан 12.2025, последняя активность 01.2026, авторы сами называют его сырым и нестабильным.
- weristvlad/max-fuck: 3 звезды, без лицензии, последняя активность 03.2026.
- Прочее (порты PyMax на Go, .NET и Laravel, расширения браузера для выгрузки своих чатов, мосты в Telegram): единицы звёзд, заброшенные или совсем свежие, без истории надёжности.

Для каждого такого варианта:

- Что даёт: любой публичный канал, на который подписан аккаунт, в реальном времени (события о новых постах) и с историей. Задержка секунды.
- Как подключить: войти личным номером, подписаться на каналы (по ссылке или через поиск), слушать события.
- Риски: блокировка или ограничение номера (единственный аккаунт владельца с личными чатами, второй завести нельзя). Типовое пользовательское соглашение на dev.max.ru запрещает автоматические скрипты и роботов, а также использование не в личных некоммерческих целях (это типовой документ для приложений разработчиков, текст пользовательского соглашения самого мессенджера отдельно не проверялся, но подход тот же). Сторонний код получает токен сессии, то есть доступ ко всем личным чатам аккаунта. Протокол неофициальный и может сломаться после любого обновления MAX.
- Трудозатраты: средние (долгоживущий процесс, переподключение, хранение сессии), плюс постоянная поддержка при изменениях протокола.
- Стоимость: бесплатно, но ценой риска для личного аккаунта.
- Вывод: рабочий путь, но только с аккаунтом, который не жалко. Личный аккаунт на сервер не переносить.

### 3. web.max.ru в браузерном профиле на локальном компьютере владельца

- Что даёт: те же каналы, что видит человек. Автоматическое чтение через автоматизацию браузера или скрипт CDP. Есть мелкие проекты, которые читают web.max.ru (например, "radar" и "cdp-reader"), но они совсем свежие, без звёзд и без гарантий.
- Подключение: отдельный профиль браузера, вход по QR с телефона владельца, скрипт на том же компьютере читает ленту каналов и шлёт посты на сервер.
- Риски: формально это тот же личный аккаунт (профиль браузера открывает сессию на нём), автоматизация против правил, вёрстка web.max.ru меняется. Не реальное время: компьютер должен быть включён.
- Трудозатраты: средние. Стоимость: бесплатно.
- Вывод: самый безопасный из способов с личным аккаунтом, потому что личные чаты остаются на машине владельца, а не на сервере. Риск блокировки номера при этом остаётся. Использовать только как опциональное дополнение.

### 4. Зеркала и каталоги каналов

- maxoteka.ru, публичные страницы (то, что используем сейчас): последние 5 постов канала, полный текст и время на странице поста, без входа. Задержка и полнота зависят от обхода каталога, частота неизвестна. Для трёх из четырёх наших каналов свежих постов в зеркале нет. Поиск по постам и архив после первой страницы доступны только после входа в кабинет. RSS у зеркала нет. Условия: robots.txt закрывает `/api/`, `/search?`, `/channel/posts-more.php`, поэтому обходить эти ограничения нельзя. Стоимость: бесплатно.
- maxoteka.ru, платный REST API (`/api/v1/`): посты канала с фильтром по дате и тексту, глобальный поиск постов по всем каналам, до 500 элементов на страницу, лимит 10 000 запросов в час. Ключ выдаётся только на высшем тарифе, 9 900 рублей в месяц (тарифы с меньшей ценой в описании API не упомянуты как дающие ключ). Это единственный найденный вариант с официально разрешённой историей и поиском по постам без личного аккаунта. Свежесть данных не заявлена, её надо проверять на пробном периоде. Для проекта-агрегатора с бесплатным MVP дорого.
- listmax.ru, maxbook.ru, catamax.ru, maxofficial.ru: каталоги со статистикой каналов (подписчики, рост, реклама). Постов каналов на публичных страницах не найдено (страницы наших каналов вернули 404 или карточку без постов). Для сбора вакансий не подходят.
- RSS: найдены только сервисы, которые публикуют в MAX из RSS (автопостинг), обратного моста "канал MAX в RSS" не найдено. Подписки на уведомления о постах чужого канала без бота-администратора или клиента от личного аккаунта нет.

### 5. Просьба к администраторам каналов

- Что даёт: самый чистый и быстрый вариант. Админ добавляет нашего бота (вариант 1) и получает события о новых постах в реальном времени с полной историей через API, либо репостит вакансии в нужный нам канал или чат.
- Риски: зависит от согласия людей. Подключать нужно по каждому каналу.
- Трудозатраты: письмо или сообщение админу, регистрация бота (профиль самозанятого или ИП проекта). Стоимость: бесплатно.
- Что предложить админам: обратная ссылка на их пост и канал, трафик на карточку вакансии, бесплатное размещение.

## Рекомендация

1. MAX остаётся дополнительным источником с задержкой через зеркало maxoteka.ru, как сейчас. По нашим данным, основная масса вакансий из MAX повторяется в Telegram и VK, поэтому потеря свежести малозаметна для пользователей. Сборщик оставить, частоту опроса не повышать (достаточно раз в 1-2 часа), паузы и ограничение пяти постов сохранить.
2. Один раз вручную проверить в приложении, живы ли vakansii_enakievo_dnr, vakansii_gorlovka и channel_rabotadnr. Если живы, а зеркало их не обновляет, выбросить их из списка зеркала и добиваться варианта 5. Если мертвы, убрать из `SOURCES`.
3. Основное усилие потратить на вариант 5: написать администраторам четырёх каналов и подключить официальный бот. Это единственный способ получить реальное время и историю законно и без риска для аккаунтов. Выполнимо, когда у проекта будет профиль самозанятого или ИП на платформе MAX для партнёров.
4. Личный аккаунт владельца на сервер не переносить ни при каких условиях: там личные чаты, а сессия неофициального клиента даёт доступ ко всему аккаунту.
5. Если реальное время всё же понадобится до согласия админов, единственный приемлемый путь с аккаунтом: отдельный браузерный профиль на локальном компьютере владельца (вариант 3) в режиме "только чтение", с пониманием, что риск блокировки номера остаётся у владельца. Автоматически решать это за владельца нельзя.
6. Платный API maxoteka (9 900 рублей в месяц) рассматривать, только если MAX станет заметным источником. Перед оплатой запросить у них пробный доступ и проверить свежесть постов по нашим каналам.

## Чего не делать

- Не обходить запреты robots.txt зеркала (`posts-more.php`, `/api/`, `/search?`) и не повышать частоту обращений.
- Не переносить личный аккаунт, токен сессии или файл сессии на сервер и не хранить их в репозитории.
- Не запускать неофициальные клиенты (PyMax и подобные) на личном номере владельца на сервере или без его явного решения.
- Не обходить капчи и защиту, не регистрировать номера для создания аккаунтов.
- Не писать из аккаунта ничего: вступление и чтение уже заметны платформе, отправка сообщений резко повышает риск блокировки.
- Не считать каталоги listmax, maxbook, catamax источником постов: они дают только статистику каналов.
- Не публиковать токены, номера телефонов и файлы сессий в репозитории и логах.

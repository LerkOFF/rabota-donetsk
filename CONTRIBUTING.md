# Правила проекта

Два правила на весь проект: интерфейс красивый с первого дня, всё проверено и покрыто тестами.

## 1. Красивый интерфейс сразу

Любая страница и любой компонент проектируются и выпускаются сразу в законченном виде. Нет "потом причешем".

- Сначала дизайн, потом вёрстка: сетка, типографика, цвета, состояния. Токены цветов, отступов и шрифтов лежат в одном месте (`web/static/tokens.css`), в компонентах только токены.
- Мобильный экран первичен: большинство соискателей ищут работу с телефона. Проверяем ширины 360, 390, 768, 1280 и 1920 пикселей.
- Светлая и тёмная темы.
- Все состояния нарисованы: загрузка, пусто, ошибка, нет результатов, слабая сеть.
- Доступность: контраст не ниже WCAG AA, управление с клавиатуры, подписи у кнопок и полей, `alt` у изображений.
- Скорость: первая отрисовка быстрая на слабом телефоне, картинки сжаты, шрифты подгружаются без скачков вёрстки.
- Карточка вакансии читается за секунду: профессия, оплата с периодом, район, график, кнопка "Позвонить". Эмодзи и капс из источников не переносим.
- Скриншоты изменённых страниц в мобильной и десктопной ширине прикладываются к каждому изменению интерфейса.

## 2. Всё проверяем, на всё есть тесты

Изменение не принимается без тестов и без зелёных проверок.

| Что | Как проверяем |
| --- | --- |
| Сборщики | тесты на сохранённых образцах ответов источников, без сети; отдельный тест на каждый источник |
| Разбор текста и оплаты | модульные тесты по каждому правилу и словарю |
| Разбор картинок | проверка на сохранённых афишах, ответ модели подменяется фикстурой |
| Качество разбора | размеченный набор из 300 постов и афиш, доля верных профессий, категорий, форматов и оплаты не ниже 90 процентов, падение доли ломает сборку |
| Склейка дублей | тесты на парах одинаковых и похожих вакансий |
| База | тесты миграций вверх и вниз, проверка индексов и поиска |
| Сайт, сервер | тесты маршрутов, фильтров, пагинации, ошибок, жалоб и удаления |
| Сайт, интерфейс | сквозные тесты в браузере на мобильной и десктопной ширине, проверка скриншотов, доступности и скорости |
| Безопасность | проверка ввода форм, защита от инъекций и подмены, лимиты запросов |
| Сборка | линтер, проверка типов, форматирование |

Правила:

- Найдена ошибка: сначала тест, который её воспроизводит, потом исправление.
- Новый источник: образец ответа в `tests/fixtures/` и тест сборщика.
- Тесты не ходят в сеть и не требуют ключей, внешние сервисы заменяются фикстурами.
- Перед отправкой изменений запускается полный набор проверок, сборка на GitHub делает то же самое.
- Результат проверки сообщается честно: что прошло, что упало, что не проверялось.

## Готово, когда

1. Интерфейс выглядит законченным на телефоне и компьютере в обеих темах.
2. Тесты написаны, проходят, набор проверок зелёный.
3. Проверено руками в браузере, не только тестами.
4. Документация в `docs/` обновлена.
